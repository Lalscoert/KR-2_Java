# Практическая №5 — решения и объяснения

**Решение 1.** Строгий разбор строки вынесен в отдельный метод `Main.parseHours`: проверяются пустая строка, ровно пять полей, целочисленность каждого поля и диапазон 0..16. Использование `split(";", -1)` сохраняет пустые поля в конце. Сообщения содержат позицию ошибочного значения.

**Решение 2.** Сумма, среднее и дни переработки вычисляются отдельными методами (`calculateTotal`, `calculateAverage`, `countOvertimeDays`). Недельная норма вынесена в константу `WEEKLY_NORM = 20`, условная трактовка варианта №3; базовое значение — 40. Точную трактовку параметра необходимо уточнить.

## Разбор ошибки из задания

`for (int i = 0; i <= hours.length; i++)` выполняет лишнюю итерацию и обращается к элементу `hours[hours.length]`, которого не существует. Правильно `i < hours.length`.

## Собственные формулировки

1. Наиболее вероятную ошибку входных данных предотвращает `parseHours`: он отклоняет неправильное количество полей, пустые и нечисловые значения до расчётов.
2. Основное бизнес-правило нормы находится в `Main` рядом с методами расчёта, поскольку программа небольшая; изменение нормы требует одной правки константы.
3. Цикл и ветвление на Activity-диаграмме соответствуют циклу `for` в `parseHours`, который проверяет каждое значение.
4. Изменение нормы должно затронуть только `WEEKLY_NORM` и соответствующий ожидаемый результат теста.
